# 合同附件脱敏实验台（纯前端）

合同附件外发前，姓名、邮箱、证件号等敏感片段常被多条规则同时命中；简单逐条替换会重复遮蔽、区间错位，甚至把未处理的敏感片段带出浏览器。本实验台把「匹配 → 裁决 → 渲染 → 复核 → 导出」做成一条可审阅的流水线，**全部计算在浏览器内完成**：不创建业务后端、不连接任何在线服务、不上传任何文本。

## 快速开始

```bash
npm install
npm run dev        # 开发服务器
npm test           # Vitest 单元测试（规则解析 / 区间裁决 / 导出链路）
npm run test:e2e   # Playwright 端到端测试（需先 npx playwright install chromium）
npm run build      # 类型检查 + 产出 dist/
```

Docker（仅静态托管，容器内没有任何业务后端）：

```bash
docker compose up --build   # http://localhost:8080
```

## 输入方式（仅三种，全部本地）

1. **粘贴文本**：直接贴入合同附件内容；
2. **本地 TXT 文件**：选择文件时必须声明编码（UTF-8 / GBK / GB18030 / Big5 / UTF-16 等）。解码失败会报出**文件名与首个失败字节位置**，不会静默替换字符；
3. **本地 JSON 规则**：格式见下。解析失败时沿用上一份有效规则，界面列出全部错误。

应用启动时会从**同源静态目录**加载 `public/samples/` 下的示例规则与示例合同，仅用于演示，不访问任何外部地址。

## 规则 JSON 格式

```json
{
  "rules": [
    {
      "id": "R1",
      "name": "身份证号",
      "pattern": "\\b\\d{17}[\\dXx]\\b",
      "flags": "",
      "priority": 100,
      "template": "[证件号]",
      "mustCheck": true,
      "enabled": true
    }
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否 | 规则编号，缺省按顺序自动编为 `R1`、`R2`…；重复编号会报错并指出两条规则的序号 |
| `name` | 是 | 规则名称，非空字符串 |
| `pattern` | 是 | 正则源文本（不含 `/` 分隔符）。非法正则会报出**规则编号与规则序号**及编译器给出的原因 |
| `flags` | 否 | 仅允许 `i`/`m`/`s`/`u` 的子集；`g` 由引擎强制附加。非法标志报出**规则编号与字符位置** |
| `priority` | 是 | 优先级，有限数值，大者优先 |
| `template` | 是 | 替换模板，支持 `$$`（字面 `$`）、`$&`（整个命中）、`$1`–`$9`（捕获组）、`$<name>`（命名组）。非法占位符报出**规则编号与模板内字符位置** |
| `mustCheck` | 否 | 是否为**导出前必检**规则（默认 `false`），见下文「必检复核」 |
| `enabled` | 否 | 初始启用状态（默认 `true`）；界面上可逐条启停，改动后立即重新计算 |

顶层也可以是纯数组 `[ {...}, ... ]`。

## 引擎工作方式

### 只在原文上匹配一次

引擎对**原始文本**收集全部启用规则的命中候选，然后一次性完成裁决与渲染。**绝不基于已替换文本继续匹配**——替换模板引入的字符不会触发新的命中，因此不会出现级联替换、重复遮蔽或区间错位。

### 稳定裁决重叠区间

同一原文区间被多条规则命中时，按以下顺序裁决，全程确定性（同样输入永远得到同样结果）：

1. **优先级**高者胜；
2. 并列时**区间更长**者胜；
3. 再并列时**规则顺序**（列表中靠前）者胜；
4. 同一规则内部按**起始位置**靠前者胜。

每个保留下来的遮蔽块都记录裁决原因与被击败的候选（规则编号、区间、落败原因），点击界面上的遮蔽块即可查看。

### 零长度匹配即失败

某条规则在原文上产生零长度命中（如 `x*`）时，无法界定遮蔽区间，**整次计算失败**，报出规则编号与字符位置；界面保留上一份有效结果，导出保持锁定。

### 必检复核（导出闸门）

渲染完成后，引擎用所有 `mustCheck: true` 的规则（**包括被界面停用的**）对**最终脱敏文本**做一次只读复核。这是验证步骤而非匹配步骤，不违反「只在原文匹配」的约束。以下任一情况都会让整次运行失败、保留上一份有效结果并锁定导出：

- 必检规则被停用，其模式残留在输出中；
- 必检命中在裁决中输给了更高优先级规则，导致部分敏感片段残留；
- 某条规则的替换模板本身写入了必检模式（模板注入）。

复核失败报出**规则编号与残留在输出中的字符区间**。

### 导出与逐项对应

通过全部校验后才能导出两个文件，二者**逐项对应**：

- `redacted.txt`：脱敏文本，与界面展示逐字一致；
- `review-checklist.json`：审阅清单，每项记录规则编号、优先级、必检标记、**原文区间与原文片段**、**输出区间与替换内容**、裁决说明。

导出前引擎会自检：清单第 N 项的 `output.start/end` 在脱敏文本中切出的内容必须等于该项记录的替换内容，`source.start/end` 在原文中切出的内容必须等于记录的原文片段，遮蔽块总数必须等于清单条目数。任何不一致都会阻止导出。

## 安全边界

- **无后端、无外发**：应用是纯静态页面，运行时只加载同源静态资源（`index.html`、示例文件）。nginx 配置带 `connect-src 'self'` 的 CSP 头，从协议层面禁止页面发起跨源请求。
- **数据不出浏览器**：粘贴的文本、选择的本地文件只进入页面内存；不会写入 `localStorage`/`IndexedDB`，刷新即清空。
- **文件读取失败不污染状态**：编码无法识别、声明编码与字节不符、JSON 语法错误、规则字段非法——都会保留上一份有效结果与上一次可导出的状态，只追加错误提示。
- **导出是显式动作**：只有点击导出按钮才生成本地下载；必检复核未通过时导出按钮锁定。
- **错误可定位**：所有错误都携带规则编号（如 `R3`）或字符/字节位置（如「第 148 字节」「输出第 4–11 字符」）。

## 项目结构

```
src/engine/    纯函数引擎：规则解析、模板、匹配、裁决、渲染、必检复核、解码、导出
src/store.ts   响应式状态：任何输入变化防抖重算；失败时保留上一份有效结果
src/components/ 界面：输入、规则、对照视图、详情、导出
tests/unit/    Vitest：规则解析、模板展开、匹配、裁决、管线、解码、导出一致性
tests/e2e/     Playwright：加载示例、点击查看、启停规则、各类失败锁定、导出对应
public/samples/ 同源静态示例（规则 + 合同文本）
```

## 测试

- `npm test`：单元测试，覆盖非法正则/非法标志/非法模板的规则编号与位置、零长度匹配、优先级与稳定性裁决、禁止基于替换文本再匹配、必检残留拦截、编码解码字节定位、导出清单逐项对应；
- `npm run test:e2e`：端到端用例，覆盖示例加载、遮蔽块点击溯源、逐条启停重算、非法规则保留旧结果、必检残留锁定导出、清单联动、导出文件逐项对应、编码错误定位。
